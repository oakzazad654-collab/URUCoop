ระบบสารสนเทศเพื่อบริหารงานสหกิจศึกษา ครอบคลุมงานนักศึกษา คณาจารย์ เจ้าหน้าที่ และผู้ดูแลระบบ

สรุปจากโครงสร้างและโค้ดใน workspace ณ วันที่ 2 ตุลาคม 2569

ภาพรวม

ระบบพัฒนาด้วย Laravel เป็นพอร์ทัลเว็บสำหรับผู้ใช้ตามบทบาท และมี REST API สำหรับจัดการข้อมูลสหกิจศึกษาแบบมีการยืนยันตัวตนและกำหนดขอบเขตข้อมูล รองรับทั้งเอกสาร CWIE รูปแบบเดิมและ workflow ข้อมูลเชิงสัมพันธ์ชุดใหม่

เป้าหมายหลักคือรวมการสมัครสหกิจศึกษา การตรวจคุณสมบัติ การจัดทำหนังสือและข้อมูลสถานประกอบการ การวางแผนปฏิบัติงาน การอนุมัติ การนิเทศ และการแจ้งผลไว้ในระบบเดียว พร้อมประวัติการดำเนินการและรายงาน

ผู้ใช้งานและสิทธิ์

บทบาทงานหลักในระบบ
นักศึกษาดูแดชบอร์ดและสถานะ จัดทำ/แก้ไขเอกสาร CWIE ของตน ส่งตรวจ และติดตามผล
อาจารย์ที่ปรึกษาดูนักศึกษาในขอบเขต ตรวจเอกสาร CWIE อนุมัติ ขอแก้ไข หรือปฏิเสธ และจัดทำคำขอออกนิเทศ CWIE 06
เจ้าหน้าที่สหกิจศึกษาจัดการสถานประกอบการและผู้ใช้ตามขอบเขต มอบหมายอาจารย์ ตรวจเอกสารและดำเนินการอนุมัติขั้นเจ้าหน้าที่
ผู้ดูแลระบบ / ผู้บริหารดูภาพรวม จัดการผู้ใช้ การอนุมัติ บันทึกตรวจสอบ และข้อมูลข้ามคณะตามสิทธิ์
อาจารย์นิเทศ / ผู้ประสานงานเข้าถึงงานที่เกี่ยวข้องกับนักศึกษา คณะ หรือคำขอนิเทศตามบทบาทที่กำหนดใน API

หน้าเว็บแบ่งกลุ่มเส้นทาง student, advisor, officer และ admin พร้อม middleware ตรวจการเข้าสู่ระบบ บทบาท และประเภทพอร์ทัล

ระบบงานและกระบวนการ

1. เอกสาร CWIE เดิม

แบบฟอร์มขอบเขตข้อมูล
CWIE 01ใบสมัครและพิจารณาคุณสมบัติ ข้อมูลนักศึกษา ประวัติการศึกษา ภาษา สุขภาพ ผู้ติดต่อฉุกเฉิน และความเห็นอาจารย์
CWIE 02คำร้องขอหนังสือถึงสถานประกอบการ รายชื่อนักศึกษา เอกสารแนบ ผลผู้ประสานงาน และผลตรวจเอกสาร
CWIE 03ข้อมูลสถานประกอบการ ผู้ประสานงาน พี่เลี้ยง งานที่ได้รับมอบหมาย แผนที่ และข้อมูลฉุกเฉิน
CWIE 04แผนปฏิบัติงานสหกิจศึกษารายสัปดาห์ ครอบคลุมแผน 16 สัปดาห์
CWIE 05โครงร่างรายงาน หัวข้อไทย/อังกฤษ รายละเอียดเนื้อหา และผู้เกี่ยวข้อง
CWIE 06คำขออนุญาตออกนิเทศงาน รายชื่อคณะนิเทศ และกำหนดการเยี่ยมสถานประกอบการ โดยอาจารย์

นักศึกษาสร้าง แก้ไข ลบ และส่งออก PDF สำหรับ CWIE 01–05 ได้ตามสถานะเอกสาร; CWIE 06 จัดทำโดยอาจารย์และส่งให้เจ้าหน้าที่พิจารณา เอกสารแนบที่พบ ได้แก่ รูปถ่ายนักศึกษาและภาพ/QR แผนที่

2. Workflow ข้อมูลสหกิจศึกษาชุดใหม่

  1. นักศึกษาสร้างใบสมัครในภาคการศึกษา ระบุสถานประกอบการ ตำแหน่ง และช่วงปฏิบัติงาน
  2. ผู้มีสิทธิ์ตรวจคุณสมบัติด้านผลการเรียน ความประพฤติ กิจกรรม และสุขภาพ พร้อมบันทึกผลพิจารณา
  3. เมื่อผ่านคุณสมบัติ จึงขอหนังสือ CWIE 02 และตรวจความครบถ้วน/อนุมัติเป็นลำดับ
  4. บันทึกสถานที่ปฏิบัติงาน CWIE 03 ผู้ติดต่อและพี่เลี้ยง แล้วระบุผลตอบรับจากสถานประกอบการ
  5. จัดทำแผนปฏิบัติงานพร้อมรายการกิจกรรม และโครงร่างรายงานเพื่อส่งอาจารย์พิจารณา
  6. จัดคำขอและตารางนิเทศ บันทึกผลการเยี่ยม ความเห็นพี่เลี้ยง/นักศึกษา ปัญหา และข้อเสนอแนะ

การอนุมัติมีสถานะและลำดับผู้พิจารณา รองรับการอนุมัติ ขอแก้ไข และปฏิเสธ พร้อมบันทึกความคิดเห็นและเวลาที่ดำเนินการ

โมดูลสนับสนุน

โมดูลความสามารถ
สถานประกอบการจัดการข้อมูลบริษัท ผู้ติดต่อ ที่อยู่ พิกัด/แผนที่ เส้นทางเดินทาง และข้อมูลสำหรับจับคู่การฝึก
บัญชีและการมอบหมายจัดการบัญชีผู้ใช้ บทบาท คณะ/สาขา และการกำหนดอาจารย์ที่ปรึกษา มีการรองรับ soft delete ของผู้ใช้
การแจ้งเตือนกล่องแจ้งเตือนในระบบและสถานะอ่านแล้ว; มีบริการส่งอีเมลและ LINE Messaging API รวมการผูกบัญชี LINE ด้วยรหัสชั่วคราวและ webhook
รายงานและแดชบอร์ดสรุปสถานะใบสมัคร สถานที่ปฏิบัติงาน การอนุมัติ เอกสารรอตรวจ และกำหนดการนิเทศ
ประวัติและตรวจสอบบันทึกการเปลี่ยนแปลง/การดำเนินการ พร้อมผู้ใช้ ตาราง รายการข้อมูล และข้อมูลก่อน-หลังตามกิจกรรมที่บันทึก
ใบสมัครฝึกงานเดิมมีหน้าจัดการใบสมัครฝึกงานแยกต่างหาก รับข้อมูลนักศึกษา/สถานประกอบการ ประวัติการศึกษาและทักษะภาษา พร้อมส่งออก PDF

ช่องทางการใช้งานและรายงาน

เว็บ: เข้าสู่ระบบด้วย session และใช้หน้าจอแยกตามบทบาท รวมแดชบอร์ด รายการอนุมัติ จัดการผู้ใช้/สถานประกอบการ แผนที่ การตั้งค่าบัญชี และกล่องแจ้งเตือน

API: เข้าสู่ระบบที่ POST /api/auth/login ด้วย identifier และ password แล้วใช้ bearer token กับเส้นทางที่ป้องกันไว้ ครอบคลุมข้อมูลนักศึกษา บริษัท ใบสมัคร คำขอ หนังสือ การจัดวางฝึก แผนงาน โครงร่างรายงาน การนิเทศ เอกสาร และการแจ้งเตือน

รายงาน API ส่งออกได้เป็น JSON, CSV และ PDF โดยมีรายงานสถานะใบสมัคร จำนวนผู้ฝึกตามสถานประกอบการ กำหนดการนิเทศ และเอกสารที่ต้องตรวจสอบ

โครงสร้างข้อมูล

ฐานข้อมูลมีข้อมูลบทบาท ภาคการศึกษา คณะ/หลักสูตร นักศึกษา บุคลากร บริษัทและผู้ติดต่อ ใบสมัครและผลตรวจคุณสมบัติ คำขอหนังสือ สถานที่ปฏิบัติงาน แผนงาน รายการกิจกรรม โครงร่างรายงาน คำขอนิเทศ ตาราง/ผลนิเทศ การอนุมัติ เอกสาร และ audit logs โดยเชื่อมโยงด้วย foreign keys และข้อกำหนดความสัมพันธ์

ข้อควรรู้: ตาราง cwie_documents เดิมและตาราง workflow เชิงสัมพันธ์ชุดใหม่เป็นคนละส่วน การเพิ่ม schema ใหม่ไม่ได้แปลงประวัติเอกสาร CWIE เดิมให้อัตโนมัติ; การใช้งานจริงควรเลือกเส้นทางข้อมูลให้ชัดเจนตาม workflow ที่ต้องการ

ความปลอดภัยและการควบคุมข้อมูล

  • API ใช้ bearer token โดยเก็บค่า SHA-256 hash แทน token จริง; จุดเข้าสู่ระบบมีการจำกัดอัตราคำขอ
  • DataAccessService จำกัดข้อมูลนักศึกษาและรายการที่เกี่ยวข้อง: นักศึกษาเห็นข้อมูลตนเอง; อาจารย์/เจ้าหน้าที่จำกัดตามคณะและสาขา; ผู้ดูแล/ผู้บริหารหรือเจ้าหน้าที่ส่วนกลางทำงานข้ามคณะได้ตามบทบาท
  • ตรวจสิทธิ์กับข้อมูลที่เกี่ยวข้องก่อนอ่าน แก้ไข อนุมัติ หรือดาวน์โหลด และการไม่พบคณะสำหรับบทบาทที่ต้องถูกจำกัดจะไม่เปิดข้อมูลออก
  • ไฟล์เอกสาร API จัดเก็บบน private local disk และใช้ชื่อไฟล์ที่ระบบสร้าง; webhook LINE ตรวจลายเซ็นตามการตั้งค่า channel secret
  • รหัสเชื่อม LINE เป็นรหัสอายุสั้นและใช้ได้ครั้งเดียว; การส่งอีเมล/LINE แบบคิวต้องตั้งค่า queue worker เมื่อใช้ asynchronous delivery

เทคโนโลยีและการติดตั้ง

โครงการใช้ Laravel 8, PHP ตามข้อกำหนด Composer ตั้งแต่ 7.3, relational database, Laravel Mix สำหรับ asset และ mPDF สำหรับ PDF โดยมีฟอนต์ TH Sarabun New สำหรับภาษาไทย

  • ตั้งค่า .env และฐานข้อมูลก่อนเรียก php artisan migrate --seed
  • กำหนด SMTP และ LINE Messaging API ผ่าน environment variables; ไม่ควรนำ token/secret ไปเก็บใน source control
  • งานแจ้งเตือนแบบคิวใช้ database queue และ php artisan queue:work --tries=3

คำเตือนการติดตั้ง: สคริปต์ SQL ที่มีการ drop/recreate ฐานข้อมูลต้องไม่ใช้กับฐานข้อมูลที่มีข้อมูลโดยไม่สำรองข้อมูลก่อน

การทดสอบที่มีใน repository

พบชุดทดสอบสำหรับการยืนยันตัวตนและบทบาท, workflow เอกสาร/อนุมัติ, การแยกข้อมูลข้ามนักศึกษาและคณะ, API สหกิจศึกษาและรายงาน, schema, แดชบอร์ด, จัดการผู้ใช้ และแผนที่สถานประกอบการ รวมถึงตรวจรูปแบบ PDF และการแนบรูปภาพ

เอกสารนี้เป็นสรุปความสามารถที่พบจาก source code, routes, migrations และ tests; การมีชุดทดสอบไม่ได้ยืนยันว่าการทดสอบทั้งหมดผ่านในสภาพแวดล้อมปัจจุบัน และไม่ได้แทนผลตรวจระบบ production
